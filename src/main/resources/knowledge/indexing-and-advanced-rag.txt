ETL indexing and advanced retrieval

ETL stands for Extract, Transform, Load. Extract uses readers to turn sources such as text files, PDFs, HTML, or JSON into Documents containing text and metadata. Transform splits large documents into focused chunks and can add summaries or keywords. Load embeds the chunks and writes them to a vector store together with the original text and metadata.

Chunking helps because a single vector for a fifty-page manual blurs many topics and forces retrieval to return far too much text. Focused chunks let search return just the useful passage and reduce irrelevant context tokens. Very small chunks can lose surrounding meaning; very large chunks can dilute relevance. Chunk size should be tested against the content and model. Token counts depend on the tokenizer, so leave room within the embedding model's input limit.

Spring AI provides TextReader, TokenTextSplitter, Document, EmbeddingModel, and VectorStore abstractions. This app reads classpath knowledge/*.txt using TextReader, preserves source, category, and topic metadata through TokenTextSplitter, and loads the chunks into SimpleVectorStore using the configured Ollama embedding model, nomic-embed-text by default. The first RAG question prepares a missing index automatically before retrieval, and concurrent first questions share one build. Later questions reuse the completed index. The rebuild button or POST /api/knowledge/index explicitly refreshes existing notes. Reindexing builds a replacement first and publishes it only after embedding succeeds; a failed rebuild preserves the last working index. The index is lost when the application restarts and is prepared again by the next RAG question. Application startup does not call the embedding provider.

Naive RAG embeds one question, searches, adds the retrieved text to a prompt, and calls the model. Advanced RAG can add stages. Before search, rewrite a question, translate it, incorporate earlier conversation context into a standalone query, expand it into several variations, or route it to an appropriate collection. Hybrid search combines semantic vector search with keyword matching. After retrieval, merge results, rerank them, remove weak matches, or compress passages before generation. Generation controls the evidence framing and refusal policy.

These advanced stages are educational concepts here. This app searches only the current message, so a follow-up such as 'what about its dimensions?' may need the topic restated explicitly. There is no query rewriting, hybrid keyword search, reranker, document upload, or production vector database in this demo.
