Building RAG with Spring AI APIs

EmbeddingModel is Spring AI's portable embedding interface. embed(String) returns one float[] vector; embed(List<String>) returns a batch List<float[]>. Provider starters such as spring-ai-starter-model-ollama or spring-ai-starter-model-openai auto-configure an EmbeddingModel. Configure the embedding model in provider properties, such as spring.ai.ollama.embedding.model. VectorStore normally calls this bean behind the scenes for both stored documents and search questions. The same embedding model and dimensions must be used in both phases, even if the chat model is different.

A Document contains text and metadata. VectorStore extends DocumentWriter and provides add(List<Document>) and similaritySearch(SearchRequest). Adding documents computes embeddings and stores them alongside text and metadata. Searching embeds the plain-text query and returns matching Documents. SearchRequest configures topK, similarityThreshold, and an optional filterExpression. A FilterExpressionBuilder can build typed expressions such as eq("topic", "rag"). String expressions such as topic == 'rag' are another supported form. Translate dynamic user choices into validated application filters rather than concatenating arbitrary input.

Purpose-built vector databases and databases with vector support use different dependencies and operational settings. A matching vector-store starter can auto-configure a VectorStore bean. This app explicitly constructs SimpleVectorStore in memory to atomically replace its published index after successful rebuilding; it uses the VectorStore interface at retrieval time. Switching a real backend also requires suitable schemas, dimensions, credentials, indexing, and filter support, not just changing a Java import.

Spring AI ETL stages are DocumentReader (Supplier<List<Document>>), DocumentTransformer (Function<List<Document>, List<Document>>), and DocumentWriter (Consumer<List<Document>>). A TextReader extracts text, TokenTextSplitter splits Documents into chunks, and VectorStore.add loads them. The pipeline can be written as vectorStore.add(splitter.split(reader.read())). Source, category, and topic metadata travel with chunks. Indexing and retrieval are separate phases. This app runs indexing before the first RAG retrieval if no index exists, shares that build across concurrent first questions, and reuses the completed index for later questions. Explicit rebuilding remains available for updated notes; no provider is contacted at startup.

Other reader options include PagePdfDocumentReader for PDFs, TikaDocumentReader for Office files and HTML, JsonReader, and MarkdownDocumentReader. Some require optional reader artifacts. KeywordMetadataEnricher and SummaryMetadataEnricher can use a chat model to attach metadata during indexing, introducing extra model calls. This demo runs only the text-reader/splitter/store pipeline; nontext readers and enrichers are educational examples.

QuestionAnswerAdvisor is the simple RAG advisor. Before the model call it takes the current user question, runs one vector-store search, stores the retrieved Documents in advisor context, and renders the question together with retrieved text. Its SearchRequest controls topK, threshold, and metadata filters. A custom PromptTemplate must contain both {query} and {question_answer_context}. The application uses system instructions and a context template that request answers only from supplied notes and acknowledge insufficient evidence.

In this app, QuestionAnswerAdvisor runs at order 0 and RagGroundingAdvisor at order 1. The second advisor checks the first advisor's retrieved Documents. If empty, it returns a refusal and never calls the chat model. If present, the chain continues. The application appends retrieved filenames from QuestionAnswerAdvisor.RETRIEVED_DOCUMENTS in response context; it does not repeat the search. Memory is outside this RAG chain and retains session/mode conversations.

The browser's RAG topic selector chooses all, rag, spring-ai, or tools. The server validates this allowlist and builds a per-request SearchRequest filter on topic metadata using FilterExpressionBuilder. It does not accept raw filter expressions. QuestionAnswerAdvisor also offers FILTER_EXPRESSION for illustrative per-call string filters; this demo configures the typed filter in the request instead. Topic filtering restricts public reference material and does not authorize private data access.

RetrievalAugmentationAdvisor is the modular RAG alternative, available in the optional spring-ai-rag module. It composes pre-retrieval, retrieval, post-retrieval, and generation stages. RewriteQueryTransformer rephrases queries, CompressionQueryTransformer incorporates conversational context, TranslationQueryTransformer changes the language, and MultiQueryExpander generates search variations. VectorStoreDocumentRetriever searches a store. ContextualQueryAugmenter frames retrieved evidence and controls empty-context handling. These stages are learning examples here, not additional live chat modes. The active path uses QuestionAnswerAdvisor and searches the current question without rewriting it from conversation history.
