The Spring AI Fundamentals application

This learning app runs Java 21 or newer with Spring Boot WebFlux and Spring AI. ChatModel is the provider abstraction; ChatClient is the fluent application-facing API for building prompts and selecting model behavior. A BOM aligns Spring AI dependency versions, and a provider starter supplies auto-configuration.

Prompts contain system, user, and assistant messages. System messages frame behavior, user messages carry the request, and prior assistant messages can provide conversational context. PromptTemplate fills placeholders. Model options such as temperature affect generation but do not guarantee correctness. ChatResponse exposes provider-dependent metadata and usage. Blocking call().content() waits for a complete answer, while stream().content() produces reactive chunks. Structured output can map generated content to Java types, but application validation is still required.

Advisors wrap ChatClient calls with reusable behavior, including memory and tool execution. Advisor request order and shared context affect how prompts are built. MessageChatMemoryAdvisor supplies recent turns from ChatMemory. This app uses a server-managed WebSession cookie for conversation identity and separates history by chat mode: tutor, rag, and tools. The New chat button clears all three mode histories in the active session. Memory is bounded, process-local, and lost on restart.

POST /api/chat accepts message and optional mode. If mode is omitted or null, the request uses rag, matching the default browser chat. RAG uses QuestionAnswerAdvisor to search bundled notes and generate from retrieved context. Before the first retrieval, a missing index is prepared automatically; concurrent first questions share the build and later questions reuse it. Preparation failures produce a setup error rather than a model-only fallback. Explicit tutor mode answers general learning questions without retrieval or tools. An optional topic field is allowed for rag requests, including requests without a mode; its values are all (default), rag, spring-ai, or tools. The server validates the topic and builds a metadata filter using FilterExpressionBuilder. Tools mode makes two read-only Java tools available to a capable chat model. All modes return Server-Sent Events named token, error, and done. Blank messages, messages longer than 2000 characters, unsupported modes, invalid topics, and topic fields on other modes are rejected before streaming.

GET /api/knowledge reports indexed, documentCount, chunkCount, embeddingModel, and indexedAt without contacting the provider. POST /api/knowledge/index explicitly rebuilds the shared in-memory learning index. Application startup does not perform indexing. The default RAG chat needs the chat model llama3:latest and embedding model nomic-embed-text installed in Ollama. After a restart, the next RAG question automatically prepares the process-local index again. OLLAMA_CHAT_MODEL, OLLAMA_EMBEDDING_MODEL, OLLAMA_BASE_URL, OLLAMA_RESPONSE_TIMEOUT, and APP_TIME_ZONE configure local operation. Tools mode requires a chat model supporting tool calls, for example llama3.1:latest. The explicitly selected general tutor mode can run without indexing or installing the embedding model.
