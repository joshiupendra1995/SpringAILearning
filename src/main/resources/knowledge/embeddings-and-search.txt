Embeddings and vector similarity search

An embedding is a numerical vector, an array of floating point numbers representing content. An embedding model maps semantically related text near each other in a vector space, even if the phrases use different words. For example, a question about resetting a password can resemble a passage about forgotten login credentials. Similarity is a learned approximation and should be evaluated on real questions.

Dimensions are the number of values in each vector. A model typically returns a fixed size independent of input text length. Some embedding models support a configurable smaller output size. More dimensions require more storage and search work; the accuracy tradeoff depends on the model and task. Indexing and querying must use the same embedding model and compatible dimensions. Changing embedding models or dimensions requires rebuilding the index. The chat model and the embedding model serve different purposes and need not be the same model.

A vector store stores embeddings, original text, and metadata. Search embeds the question, compares the query vector with stored vectors, and returns the original text for the nearest matches. It never decodes a vector back into text. Purpose-built stores include Chroma, Pinecone, Weaviate, Milvus, and Qdrant. Databases such as PostgreSQL with pgvector, Redis, and MongoDB Atlas also support vectors. SimpleVectorStore is an in-memory teaching implementation rather than a production database.

Top K limits how many matching chunks are returned. A similarity threshold filters weak matches; increasing it can reduce noise but can also omit useful context. This app defaults to top K of 3 and threshold 0.45. There is no universal correct threshold: tune retrieval with representative questions and known answers.

Metadata such as source filename, category, product version, language, or tenant can accompany each chunk. Metadata filters constrain a semantic search to an allowed subset. This app attaches source, category, and topic metadata. RAG mode allows a topic filter: all, rag, spring-ai, or tools. The server builds an equality filter over topic using FilterExpressionBuilder and applies it in SearchRequest before the QuestionAnswerAdvisor searches. It accepts no raw filter strings from the browser. This public-note topic selector is a relevance control, not an authorization boundary. In a private multi-tenant system, authorization filters must be derived from trusted application identity and enforced in retrieval code, not delegated to a model.
